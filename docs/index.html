AUTONOMOUS LLM

Your project. Your decision.

Live

  1. No form to learn. A sentence typed on the board, spoken to TALK from your phone, or the first step of a saved automation. You: Type or say what you want, from any device.

  2. Most questions never need an agent. The router walks a ladder and stops at the first rung that can answer, so you are not paying a model to tell you the time. You: Nothing. The hub picks the cheapest way.

  3. One planner reads the ask and proposes the pieces. Briefs that do not depend on each other run side by side; one that needs earlier work waits for it. You: Nothing, unless it asks you a question.

  4. Each mission gets its own git worktree on its own branch. Your files do not change while it runs, and a provider hiccup moves the run to the next model instead of failing it. You: Nothing. Watch it appear in the Git Graph if you like.

  5. An agent at a real fork does not guess. The run parks, the question reaches whichever device is open, and your answer resumes the same mission. It never asks for a password or a key. You: Answer the question from whichever device you have.

  6. When the work is done the mission stops with the diff beside it. This is the one decision the system will not make for you. You: Read the diff. This part is yours.

  7. Apply merges the branch into your repo. Discard removes the copy and the branch. An automation waiting on this carries on only if you applied. You: Press APPLY to merge it, or DISCARD to throw it away.

MCP CONTROL

It asks before it presses anything.

Unit-tested

  1. “Open Apple Music and play my liked songs.” Speak to TALK or type it. No scripting, no recorded macro to maintain. You: Say or type what you want done.

  2. Windows MCP reads the controls on screen, so it finds Play by what it is, not by where it was last time. You: Nothing.

  3. It shows the control it found and waits for your yes before touching anything. You: Look at the press it shows, then say yes or no.

  4. Windows MCP presses the control. Shell, registry, file and process tools are switched off, so it can drive apps but not rewrite the machine. You: Nothing. It cannot rewrite the machine.

  5. A press only counts if the window changed. A replay that leaves the window as it was is not counted as a success. You: Nothing.

  6. A run that worked is saved as a routine. It starts as a candidate and is trusted only after it has worked twice. You: Nothing. Ask again later and it replays.

AGENTS + SKILLS

A team you can read and extend.

Live

  1. The voice you talk to: Talk, spoken answers, and the Hub's own commands. You: Press TALK, then speak or type. Smith answers out loud and on screen, and hands the job to whoever should do it.

  2. Designs a new agent from a plain description and hands back one ready-to-save file. You: Describe the job in plain words, read the file Neo hands back, and save it. The new agent joins your team.

  3. Diagnoses the Hub when something is wrong and proposes a fix as a diff in Missions. Never restarts anything. You: Say “Smith, something is wrong” or press ASK THE DOCTOR on a red item. Read the diff and press APPLY. Restarting stays yours.

  4. Presses and types in apps on this PC for a goal, one step at a time, checking the screen after each. You: Say what you want done. It shows each press and asks first.

  5. Asks what it must, then splits your ask into steps, independent ones side by side. Writes no code. You: Answer its question if it asks one. Otherwise nothing.

  6. Ships the smallest change that works, in the project's own style. Leaves what you didn't ask about alone. You: Nothing. You read the result in the diff.

  7. The skeptic. Never edits; says ship, changes-needed or blocked, and points at the line. You: Read its verdict, then the diff.

  8. Tries to break it before you do: writes the tests, runs them, reports what failed and why. You: Nothing. The failures show up in the review.
