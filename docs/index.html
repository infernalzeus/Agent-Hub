Autonomous missions

A request that changes code. Hover or tap a step.

  1. 1
    AskType it or say it

    No form to learn. A sentence typed on the board, spoken to TALK from your phone, or the first step of a saved automation.

  2. 2
    RouteCheapest answer first

    Most questions never need an agent. The router walks a ladder and stops at the first rung that can answer, so you are not paying a model to tell you the time.

  3. 3
    PlanSplit it into briefs

    One planner reads the ask and proposes the pieces. Briefs that do not depend on each other run side by side; one that needs earlier work waits for it.

  4. 4
    WorkIn a private copy

    Each mission gets its own git worktree on its own branch. Your files do not change while it runs, and a provider hiccup moves the run to the next model instead of failing it.

  5. 5
    Ask youIt parks if it is stuck

    An agent at a real fork does not guess. The run parks, the question reaches whichever device is open, and your answer resumes the same mission. It never asks for a password or a key.

  6. 6
    ReviewRead the diff

    When the work is done the mission stops with the diff beside it. This is the one decision the system will not make for you.

  7. 7
    ApplyOr discard

    Apply merges the branch into your repo. Discard removes the copy and the branch. An automation waiting on this carries on only if you applied.

PC control Unit-tested

Windows MCP, driven by plain words. Hover or tap a step.

  1. 1
    Say itIn plain words

    “Open Apple Music and play my liked songs.” Speak to TALK or type it. No scripting, no recorded macro to maintain.

  2. 2
    LookFind it by name, not by pixel

    Windows MCP reads the controls on screen, so it finds Play by what it is, not by where it was last time.

  3. 3
    Ask firstYou see the press before it happens

    It shows the control it found and waits for your yes before touching anything.

  4. 4
    ActClick, type, open

    Windows MCP presses the control. Shell, registry, file and process tools are switched off, so it can drive apps but not rewrite the machine.

  5. 5
    CheckDid it actually work?

    A press only counts if the window changed. A replay that leaves the window as it was is not counted as a success.

  6. 6
    RememberLearned once, replayed after

    A run that worked is saved as a routine. It starts as a candidate and is trusted only after it has worked twice.
